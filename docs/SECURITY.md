# セキュリティ & 安全性設計 (SECURITY.md)

## 1. 脅威モデル

devclean の最優先命題は「保護対象ファイルの誤削除の完全防止」です。
以下の脅威・リスクに対して設計レベルで防御します。

1. **Git管理ファイルの誤認削除**:
   - `git add -f` などで強制的にインデックスに追加されたファイルは、`.gitignore` ルール上は ignore パターンに一致します。
   - **対策**: `git check-ignore --no-index` の結果に関わらず、`git ls-files` に存在するすべてのパスを最優先で保護します。
2. **ディレクトリ集約による巻き込み**:
   - `target/` や `node_modules/` の中に重要なファイルやTrackedファイル、機密ファイルが含まれている場合、ディレクトリ単位の移動で巻き込まれるリスク。
   - **対策**: 配下にTrackedファイル、Level 1/2 機密ファイル、シンボリックリンク、ネストした `.git` が1件でも存在する場合、ディレクトリ全体の集約移動を拒否します。
3. **リンク追従による実体破壊**:
   - シンボリックリンクやジャンクションを追従して削除を実行すると、プロジェクト外部の重要データが削除される危険。
   - **対策**: 走査ライブラリの `follow_links(false)` を徹底し、リンク先を一切辿りません。
4. **機密情報の漏洩・破棄**:
   - `.env` や SSH秘密鍵などの不注意な削除。
   - **対策**: プロジェクトルートから深さ0〜2の機密ファイルは、いかなるオプション（`--include-sensitive` や `--include`）でも保護を解除できません。
5. **TOCTOU (Time-of-Check to Time-of-Use) 競合**:
   - 走査完了から削除実行までの間にファイルが差し替えられたり、Git追跡対象が追加されるリスク。
   - **対策**: 削除の直前にメタデータとTracked状態を再検証します。
